# ADR 0002 — Fastify + Drizzle instead of NestJS

**Status:** Accepted · 2026-09-25

## Context

The first recommendation was NestJS. At build time NestJS 12 had just become ESM-only (Aug 2026),
and its decorator-based dependency injection ties the project to specific TypeScript compiler
modes. The API is a modular monolith whose main complexity is authorisation, which is plain
functions either way.

## Decision

Fastify 5 with explicit modules (`<module>.routes.ts` → `<module>.service.ts`), zod validation
from `@helm/shared`, and Drizzle ORM with SQL migrations generated by drizzle-kit.

## Consequences

- Less framework, fewer abstractions to learn; everything is visible in plain TypeScript.
- Conventions that NestJS would impose are ours to keep: see the
  [folder structure](../architecture/folder-structure.md).
- Drizzle keeps SQL close to what runs; migrations are reviewed as SQL in pull requests.
